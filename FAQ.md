# SKYNZ — Current Beta FAQ

*Updated November 2026. This FAQ distinguishes working source, experimental branches, design mockups and capabilities not yet offered to customers.*

## Is SKYNZ ready to buy?
No paid creator-page purchase or production NFT mint is verified as live in the inspected SKYNZ application code. SKYNZ is preparing a limited creator-page beta; check [skynz.site](https://www.skynz.site/) for the latest published status. Do not send money or connect a wallet based on an older marketing draft.

## What can a beta creator do?
The **intended minimum beta** lets a creator set up a page, customize its look, add approved media and social links, preview, save, reopen, edit and publish. The repository has implementations for portions of this workflow; the integrated application must pass account, database, permission and Windows/public deployment tests before beta acceptance.

## Are the luxury, pink/glam, and dark dashboards fully functional?
The showcased designs are visual references. They set the target for reusable creator-page templates, not proof that every illustrated earnings number, social feed, badge, or player is live.

## Does the AI assistant Lippy already build a complete page?
Prototype AI-assisted page-draft code exists in a development pull request. It uses a constrained model response that the creator reviews before saving. It has not yet been accepted as a complete hosted, production-ready visual page builder.

## Is a VR/game interface required?
No. The initial creator-page beta uses conventional browser controls. Immersive/game-style Creator Forge may be offered as an optional later interface.

## Will a free beta creator lose their page on upgrade?
The launch design requires keeping the same page ID, handle, content and page address when the creator **optionally** mints ownership later. This must be implemented, backed up, and verified before it is promised as a public contractual guarantee. Publishing, data portability and account-retention terms will be explicit.

## Does SKYNZ mint real ownership tokens now?
Not yet as a verified paid production feature. The main application has a placeholder badge endpoint, and another development branch intentionally returns HTTP 501 to avoid pretending a mint occurred. Real ownership minting, if launched, needs signed Solana transactions, verified owner identity, metadata, duplicate prevention and tested recovery. Initial tests should use Solana devnet (test assets have no mainnet ownership effect).

## Does owning a token guarantee my website stays online?
No. Blockchain token ownership and website hosting/content availability are separate systems. SKYNZ needs clear terms for hosting, backups, publishing rights, transfers and ownership verification.

## Are smart contracts audited and resale royalties guaranteed?
No independent security audit was verified in the reviewed materials, and no production royalty-enforcement guarantee has been established. Historical Anchor contract drafts and promotional figures should not be treated as deployed, audited contracts or guaranteed resale income.

## Is a $199 one-time purchase already available?
No current price or live checkout was verified. Earlier one-time price points are historical proposals, not a confirmed offer. Any future purchase, network, storage and service fees must be clearly disclosed.

## Can I earn 95% of sales or passive income through SKYNZ?
Do not rely on old marketing percentages or revenue examples. There is currently no verified production payment/payout system, and no returns are guaranteed. Actual monetization terms will need published contracts and tested settlement.

## Are Spotify, YouTube and live broadcasts supported?
Source code includes external links and some Spotify/YouTube embedding support. Individual providers can restrict playback or framing. Actual multistream broadcast control through OBS/Restream and its analytics are not yet a verified production service.

## Does SKYNZ collect or sell personal data?
The production privacy policy and actual implementation must be reviewed before launch. The design aims for minimal information, restricted AI tool access, and creator-controlled permissions; these goals should not be represented as completed regulatory certification or verified data-handling guarantees.

## How can I participate?
Follow the verified updates on [skynz.site](https://www.skynz.site/). Any testing invitation must explain whether it is a free preview or production service, what data is stored, and whether any later minting is optional.

## Which repositories show current engineering work?
See [SKYNZ-2.0](https://github.com/Justelliott6/SKYNZ-2.0) and its [open AI Creator Control Center PR #2](https://github.com/Justelliott6/SKYNZ-2.0/pull/2). A merged or successfully compiled branch is **not** automatically proof of local or public end-to-end acceptance.
